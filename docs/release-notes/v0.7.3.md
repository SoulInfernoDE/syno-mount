Syno Mount 0.7.3 makes key login work for accounts whose home folder DSM created with Windows ACLs.

## New

- **The assistant names the cause.** When the NAS accepts the password but refuses the installed key because the home folder, `.ssh` or `authorized_keys` carry Windows ACLs (they show `777`), the assistant says so, with the modes it found, instead of asking to check the password.
- **"Prepare key login" in the administrator area** (Accounts on the NAS › By account): Syno Mount shows the exact commands, asks for the administrator's password again (DSM wants it before anything runs as root), runs them once as root through DSM's Task Scheduler and deletes the task. The home folder, `.ssh` and `authorized_keys` lose their ACLs and get 755, 700 and 600; keys already in the file stay.

## Safety

- The commands never follow a link: the account owns its home folder and could put a link there that root would otherwise follow. Root first takes the home folder and `.ssh` so that nothing can be swapped meanwhile, refuses links and hard-linked files, and gives both folders back to the account at the end, also when a step fails. Tested on Virtual DSM with links to root's files and a hard link to another account's key file: each refused, the targets unchanged.
- If the task cannot be deleted from the Task Scheduler, the error says so and names the task.

## Known limits

- The HTTPS tunnel is still Linux only.

## Downloads

Linux: `.deb`, `.rpm`, `.AppImage` for x86_64 and arm64. Windows: `-setup.exe` (per user) or `.msi`; the installers are not signed yet, so SmartScreen may warn. Check with `sha256sum -c SHA256SUMS.txt`.

## Deutsch

Syno Mount 0.7.3 lässt die Schlüssel-Anmeldung auch bei Konten funktionieren, deren Home-Ordner DSM mit Windows-ACLs angelegt hat.

### Neu

- **Der Assistent nennt die Ursache.** Nimmt das NAS das Passwort an, lehnt aber den installierten Schlüssel ab, weil Home-Ordner, `.ssh` oder `authorized_keys` Windows-ACLs tragen (sie zeigen `777`), sagt der Assistent das mit den gefundenen Rechten, statt das Passwort prüfen zu lassen.
- **„Schlüssel-Login vorbereiten“ im Adminbereich** (Konten auf dem NAS › Nach Konto): Syno Mount zeigt die genauen Befehle, fragt erneut nach dem Administrator-Passwort (DSM verlangt es, bevor etwas als root läuft), führt sie einmal als root über DSMs Aufgabenplaner aus und löscht die Aufgabe wieder. Home-Ordner, `.ssh` und `authorized_keys` verlieren ihre ACLs und bekommen 755, 700 und 600; vorhandene Schlüssel in der Datei bleiben.

### Sicherheit

- Die Befehle folgen nie einem Link: Das Konto besitzt seinen Home-Ordner und könnte dort einen Link ablegen, dem root sonst folgen würde. Root übernimmt zuerst den Home-Ordner und `.ssh`, damit währenddessen nichts ausgetauscht werden kann, lehnt Links und hart verlinkte Dateien ab und gibt beide Ordner am Ende dem Konto zurück, auch wenn ein Schritt scheitert. Getestet auf Virtual DSM mit Links auf Dateien von root und einem harten Link auf die Schlüsseldatei eines anderen Kontos: jeweils abgelehnt, die Ziele unverändert.
- Lässt sich die Aufgabe nicht aus dem Aufgabenplaner löschen, sagt der Fehler das und nennt die Aufgabe.

### Bekannte Grenzen

- Den HTTPS-Tunnel gibt es weiterhin nur unter Linux.

### Downloads

Linux: `.deb`, `.rpm`, `.AppImage` für x86_64 und arm64. Windows: `-setup.exe` (pro Benutzer) oder `.msi`; die Installer sind noch nicht signiert, SmartScreen kann deshalb warnen. Prüfen mit `sha256sum -c SHA256SUMS.txt`.
