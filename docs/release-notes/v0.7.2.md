Syno Mount 0.7.2 makes the internet route work more reliably and say why it fails, tested with Linux and Windows against a real NAS.

## Fixed

- **Every failure names its reason.** Instead of "does not answer on any address", the journal (Linux) and the folder's log (Windows) say for each address what happened, for example `LAN 192.168.1.20:22: timed out; internet nas.example.org:2222: [2001:db8::5]:2222: connection refused, 203.0.113.7:2222: no route to host`, or that no internet address is set, or that the proxy does not pass Syno Mount on.
- **The LAN route needs SSH, not just an open port.** In a foreign network another device may have the same private address; the internet address is now tried instead of failing again and again.
- **More time over the internet:** 5 s per step instead of 1.5 s, which TLS through a proxy over a slow line needs.
- **Every address of a name is tried**, IPv6 and IPv4, for direct SSH and for the HTTPS tunnel.
- **The assistant can check an internet address** and trust a proxy certificate, as the settings could already. A new folder takes over the internet address of the other folders of the same NAS, and a changed address reaches the folders that still had the old one.
- **Typing addresses:** `https://…` or port 443 ticks "Through HTTPS", `user@host` is understood, IPv6 addresses work with sshfs.
- **Keys are removed from the NAS by the key itself**, so two computers with the same name keep their own keys; removing a folder away from home goes over the internet address.
- A Windows self-test no longer leaves its empty test folder behind.

## Known limits

- DSM creates home folders with Windows ACLs; SSH then refuses the installed key. The README says how an administrator fixes this once per account; the app will do it in a later version.
- The HTTPS tunnel is still Linux only.

## Downloads

Linux: `.deb`, `.rpm`, `.AppImage` for x86_64 and arm64. Windows: `-setup.exe` (per user) or `.msi`; the installers are not signed yet, so SmartScreen may warn. Check with `sha256sum -c SHA256SUMS.txt`.

## Deutsch

Syno Mount 0.7.2 macht den Internet-Weg zuverlässiger und lässt ihn sagen, warum er scheitert, getestet mit Linux und Windows gegen ein echtes NAS.

### Behoben

- **Jeder Fehlschlag nennt seinen Grund.** Statt „does not answer on any address“ sagen das Journal (Linux) und das Protokoll des Ordners (Windows) für jede Adresse, was passiert ist, zum Beispiel `LAN 192.168.1.20:22: timed out; internet nas.example.org:2222: [2001:db8::5]:2222: connection refused, 203.0.113.7:2222: no route to host`, oder dass keine Internet-Adresse eingetragen ist, oder dass der Proxy Syno Mount nicht weiterleitet.
- **Die LAN-Route braucht SSH, nicht nur einen offenen Port.** In einem fremden Netz kann ein anderes Gerät dieselbe private Adresse haben; jetzt wird stattdessen die Internet-Adresse versucht, statt immer wieder zu scheitern.
- **Mehr Zeit über das Internet:** 5 s pro Schritt statt 1,5 s, wie TLS über einen Proxy auf einer langsamen Leitung sie braucht.
- **Jede Adresse eines Namens wird versucht**, IPv6 und IPv4, für direktes SSH und für den HTTPS-Tunnel.
- **Der Assistent kann eine Internet-Adresse prüfen** und einem Proxy-Zertifikat vertrauen, wie es die Einstellungen schon konnten. Ein neuer Ordner übernimmt die Internet-Adresse der anderen Ordner desselben NAS, und eine geänderte Adresse erreicht die Ordner, die noch die alte hatten.
- **Adressen eingeben:** `https://…` oder Port 443 setzt „Über HTTPS“, `user@host` wird verstanden, IPv6-Adressen funktionieren mit sshfs.
- **Schlüssel werden auf dem NAS über den Schlüssel selbst entfernt**, sodass zwei Computer mit gleichem Namen ihre eigenen Schlüssel behalten; das Entfernen eines Ordners außer Haus läuft über die Internet-Adresse.
- Ein Selbsttest unter Windows lässt seinen leeren Testordner nicht mehr zurück.

### Bekannte Grenzen

- DSM legt Home-Ordner mit Windows-ACLs an; SSH lehnt dann den installierten Schlüssel ab. Die README erklärt, wie ein Administrator das einmal pro Konto behebt; die App wird das in einer späteren Version selbst erledigen.
- Den HTTPS-Tunnel gibt es weiterhin nur unter Linux.

### Downloads

Linux: `.deb`, `.rpm`, `.AppImage` für x86_64 und arm64. Windows: `-setup.exe` (pro Benutzer) oder `.msi`; die Installer sind noch nicht signiert, SmartScreen kann deshalb warnen. Prüfen mit `sha256sum -c SHA256SUMS.txt`.
